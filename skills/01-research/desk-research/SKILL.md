# Кабинетное исследование

Цель – собрать проверяемую картину по вопросу из уже существующих источников, не проводя собственных интервью.

## Вход

- Исследовательский вопрос (один-три). Если вопроса нет – сформулируй его вместе с человеком: «что нам нужно узнать, чтобы принять какое решение?»
- Ограничения: срок, регион (РФ / мир), отрасль, какие источники допустимы.

## Шаги

### 1. Сформулируй вопросы и критерии остановки

- Разбей главный вопрос на 3–7 подвопросов.
- Для каждого определи: какой ответ нужен (число, список, пример, мнение эксперта), и когда остановиться (например, «три независимых источника сходятся»).

### 2. Составь карту источников

Ищи в порядке надёжности:

1. **Первоисточники** – законы и нормативные акты, официальная документация вендоров, отчёты компаний, статистика (Росстат, ЦБ, hh.ru Insights), научные публикации.
2. **Внутренние источники** – регламенты, обращения в поддержку, выгрузки из систем, прошлые исследования, протоколы встреч.
3. **Экспертные** – конференции, доклады практиков, отраслевые исследования (с методологией).
4. **Вторичные** – статьи, обзоры, блоги. Использовать только как наводку на первоисточник.

Форумы и комментарии – только для поиска формулировок и болей пользователей, не для фактов.

### 3. Ищи широко, потом узко

- Начни с коротких запросов из 1–3 слов, потом уточняй.
- Каждый новый запрос должен отличаться от предыдущих по сути, а не перестановкой слов.
- Ищи на русском и на английском: часть практик описана только на одном языке.
- Для сравнения решений ищи по каждому кандидату отдельно, а не одним запросом на всех.
- Когда подходит несколько ответов – ищи то, что отличит их друг от друга, а не только подтверждения любимой версии.

### 4. Фиксируй каждую находку с источником

Для каждого факта сразу записывай: утверждение своими словами, ссылку, дату публикации, тип источника, уровень доверия (см. `fact-check`).

### 5. Обзор аналогов и решений (если нужен)

Для сравнения «строить или покупать» составь таблицу по одинаковым критериям:

| Критерий | Вариант A | Вариант B | Своя разработка |
|---|---|---|---|
| Закрывает ключевые сценарии (какие) | | | |
| Размещение (облако / on-premise) | | | |
| Соответствие требованиям ИБ и 152-ФЗ | | | |
| Интеграции с нашими системами | | | |
| Стоимость владения за 3 года | | | |
| Зависимость от вендора, наличие в реестре российского ПО | | | |
| Срок до первой ценности | | | |

Пустая ячейка – это `OPEN`, а не «нет».

### 6. Синтез

- Ответь на каждый подвопрос: что известно, насколько уверены, что осталось неизвестным.
- Отдельно – противоречия между источниками.
- Отдельно – выводы для нашего контекста (что из этого применимо, что нет и почему).

## Формат результата

```markdown
# Исследование: <вопрос>

## Короткий ответ
3–5 предложений.

## Ответы по подвопросам
### <подвопрос>
- Вывод … (уверенность: высокая/средняя/низкая) [источник]

## Противоречия
## Применимость к нашему контексту
## Открытые вопросы
## Источники
- [Название](ссылка) – тип, дата
```

## Правила

- Пересказывай своими словами. Дословные цитаты – только когда важна точная формулировка, коротко и с кавычками.
- Не приписывай источнику того, чего в нём нет. Не уверен – не пиши.
- Свежесть важна: для технологий, цен, законов – ищи публикации последнего года и указывай дату.
