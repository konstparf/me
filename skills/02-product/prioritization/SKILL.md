# Приоритизация

Цель – прозрачное решение «что первым и почему», которое можно объяснить и пересмотреть, когда появятся новые данные.

## Шаг 1. Свяжи всё с результатом (дерево возможностей)

```
Результат (бизнес-цель, измеримая)
 └─ Возможность (потребность/боль пользователя из исследования)
     └─ Решение (идея)
         └─ Эксперимент (как проверим)
```

- Наверху – один результат, а не список пожеланий («снизить нагрузку на HR-специалистов по рутинным запросам на 30%»).
- Возможности формулируй как проблемы пользователей, не как фичи.
- Для каждой возможности – минимум 2–3 альтернативных решения, чтобы не влюбляться в первое.
- Решения без связи с результатом – кандидаты на «не делаем».

## Шаг 2. Выбери метод под ситуацию

| Ситуация | Метод |
|---|---|
| Много разнородных идей, нужно быстро отсеять | ICE: Impact × Confidence × Ease, по 1–10 |
| Бэклог фич с понятным охватом | RICE: Reach × Impact × Confidence / Effort |
| Есть сроки, регуляторика, окна возможностей | Стоимость задержки (Cost of Delay) и CD3 = CoD / длительность |
| Нужно понять, какие функции базовые, а какие радуют | Kano: обязательные / линейные / восхищающие / безразличные |
| Спор стейкхолдеров | Явные критерии с весами, оценки каждого, обсуждение расхождений |

## Шаг 3. Оцени с обоснованием

Для каждой оценки – строка «почему так». Уверенность (Confidence) ставь по доказательствам, а не по ощущению:

| Confidence | Основание |
|---|---|
| 0.1–0.3 | Мнение, интуиция, запрос одного человека |
| 0.5 | Несколько интервью, косвенные данные |
| 0.8 | Данные из систем, подтверждённые интервью |
| 1.0 | Результаты эксперимента или пилота |

Для внутренних сервисов охват (Reach) считай в сотрудниках или операциях за период; влияние – в сэкономленных часах, снижении ошибок, нагрузки на поддержку; не забывай про обязательные требования (закон, ИБ, аудит) – они идут отдельной полосой и не конкурируют по баллам.

## Шаг 4. Сформируй решение

- Топ-3 с аргументами.
- Что сознательно не делаем сейчас и почему (это важнее топа).
- Зависимости и риски.
- Когда пересмотрим (событие или дата).

## Шаг 5. Объясни отказ заказчику

Шаблон: «Мы сравнивали по <критерии>. Ваша задача получила <оценку>, потому что <основание>. Что может изменить приоритет: <данные, которые стоит принести>. Альтернатива сейчас: <упрощение / обходной путь>.»

## Формат результата

```markdown
# Приоритеты: <область>, <дата>

## Результат, на который работаем
## Дерево возможностей (кратко)
## Оценка
| Идея | Охват | Влияние | Уверенность | Затраты | Балл | Обоснование |
## Решение
1. … – почему
## Не делаем сейчас
## Пересмотр
```

## Анти-паттерны

- Баллы, подогнанные под заранее выбранный ответ.
- Одинаковая уверенность у всех идей.
- Приоритет по громкости заказчика.
- Список из 30 «приоритетов».
