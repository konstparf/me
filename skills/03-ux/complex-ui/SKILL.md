# Сложные рабочие интерфейсы

Цель – интерфейс, в котором человек, работающий в нём весь день, делает частое быстро, не теряет контекст и не ошибается в важном. Красота вторична, скорость и ясность – главное.

Этот скилл дополняет `ui-design` (общие принципы, формы, состояния) и `prototyping` (как собрать прототип). Здесь – то, чего нет в потребительских интерфейсах.

## Когда интерфейс «сложный»

По NN/g, сложное приложение – это нелинейные задачи опытных пользователей. Признаки (достаточно двух-трёх):

- Человек проводит в интерфейсе значительную часть рабочего дня.
- Сотни и тысячи записей, которые надо искать, сравнивать, обрабатывать пачками.
- Задачи не сводятся к одному сценарию: разбор, расследование, исключения.
- Несколько ролей и передача работы между ними.
- Цена ошибки высокая: деньги, зарплата, персональные данные, юридические последствия.

Если признаков нет (сотрудник раз в год подаёт заявку) – достаточно `ui-design`: там важнее простота, чем скорость эксперта.

## Шаг 0. Модель работы до экранов

Перед рисованием ответь письменно – иначе выйдет красивая витрина вместо рабочего места:

```markdown
## Модель работы
Роли и их доля времени в интерфейсе: HR-специалист – 6 ч/день; руководитель – 10 мин/день; …
Объекты и связи: Сотрудник 1–N Заявка; Заявка N–1 Подразделение; …
Объёмы: записей в главном списке – ~3 000; новых в день – ~150; полей в карточке – ~40
Топ-5 действий по частоте (из интервью или логов): 1. … 2. …
Топ-3 действия по цене ошибки: …
Откуда приходит работа: очередь / уведомление / поиск / звонок
Где пользователь теряет время сейчас: …
```

Частота решает, что вынести на первый уровень и дать горячую клавишу. Цена ошибки решает, где добавить трение (подтверждение, предпросмотр, второе лицо).

## Шаг 1. Архетип экрана

Каждый экран – один из архетипов. Выбирай по задаче, а не по привычке «везде таблица».

| Архетип | Задача пользователя | Когда | Пример |
|---|---|---|---|
| **Очередь (инбокс)** | Разобрать входящее по одному | Работа приходит потоком, важен порядок и SLA | Согласования руководителя, обращения в HR |
| **Коллекция (таблица)** | Найти, сравнить, обработать пачкой | Много однотипных записей, много полей | Реестр сотрудников, список заявок |
| **Таблица + панель (split view)** | Пройтись по записям, не теряя список | Детали не влезают в строку, но часто нужно сравнивать | Проверка документов, разбор ошибок интеграции |
| **Карточка записи** | Понять всё об одном объекте и действовать | Объект с историей и связями | Карточка сотрудника, сделки, кандидата |
| **Хаб** | Увидеть объект и превью связанных | У объекта много связанных сущностей | Подразделение: люди, вакансии, бюджет |
| **Мастер (шаги)** | Пройти длинный редкий процесс без ошибок | Редкое, много полей, порядок важен | Приём на работу, массовая индексация |
| **Доска (канбан)** | Видеть этапы и двигать между ними | Мало этапов (до 6–7), важен поток | Воронка подбора |
| **Календарь / таймлайн** | Увидеть пересечения во времени | Даты и длительности – суть задачи | График отпусков подразделения |
| **Дашборд** | Понять, всё ли в порядке, и куда смотреть | Мониторинг, руководитель | Просрочки согласований, нагрузка команды |

Правила выбора:
- Карточка записи **не заменяется** боковой панелью: панель – для быстрого просмотра, у объекта всегда есть своя страница с адресом (ссылку можно отправить коллеге).
- Модальное окно – только для коротких действий, которые прерывают работу сознательно (подтверждение необратимого). Для просмотра и правки – боковая панель или страница: модалка закрывает контекст.
- Канбан на 15 колонках и календарь с 300 людьми не работают – переходи к таблице с группировкой.

## Шаг 2. Каркас приложения

```
┌──────────────────────────────────────────────────────────────┐
│ [≡] Логотип   [ Поиск и команды  Ctrl+K ]   🔔 3   [Аня ▾]   │
├────────┬─────────────────────────────────────────────────────┤
│ Задачи │ Заявки › Отпуск › №1042                [Действия ▾] │
│  (12)  │                                                     │
│ Заявки │   рабочая область                                   │
│ Люди   │                                                     │
│ Отчёты │                                                     │
│ ─────  │                                                     │
│ Настр. │                                                     │
└────────┴─────────────────────────────────────────────────────┘
```

- **Левая навигация** по объектам и задачам пользователя, сворачивается до иконок. Счётчики только там, где они зовут к действию («Задачи 12»), а не везде.
- **Глобальный поиск и командная палитра** в одном поле, `Ctrl/⌘+K`: поиск записей, переход к разделу, действие («Создать заявку»), недавнее. Для эксперта это главный способ навигации.
- **Хлебные крошки** на всех вложенных страницах – путь к списку, из которого пришёл.
- **Контекст** (компания группы, роль, подразделение) – явный переключатель в шапке, если у человека их несколько. Текущий контекст виден всегда: действие «не в той компании» – типичная дорогая ошибка.
- **Контент важнее хрома**: тонкая шапка, сворачиваемая навигация, никаких декоративных баннеров в рабочей области.

## Паттерны

### 1. Таблицы и коллекции

- Текст – влево, количественные числа – вправо и моноширинными цифрами (`font-variant-numeric: tabular-nums`), ничего по центру.
- Заголовок закреплён при прокрутке; первая колонка (кто / что) закреплена при горизонтальной прокрутке.
- Колонки: по умолчанию – только нужные для топ-задач; остальные пользователь добавляет сам. Порядок, ширина, видимость сохраняются; есть «Сбросить вид».
- Сортировка по умолчанию – по смыслу работы: срочное или новое сверху.
- Действия над строкой – по наведению и в меню «⋯»; плюс открытие записи кликом по строке.
- Детали строки, от лёгкого к тяжёлому: подсказка → раскрывающаяся строка → боковая панель → страница записи. Выбирай самый лёгкий, которого хватает.
- Общее количество записей видно всегда («Найдено 1 248»). Пагинация – когда важно «вернуться на то же место» и печатать; бесконечная подгрузка – для ленты; виртуализация – для тысяч строк в одном списке.
- Зебру не используй по умолчанию: с ней хуже видны наведение, выделение и фокус.

### 2. Фильтры, поиск, сохранённые представления

- Быстрые фильтры (2–4 самых частых) – чипами над таблицей; остальные – в панели «Фильтры». Активные фильтры всегда видны и снимаются по одному.
- Поиск подсвечивает совпадения в строках.
- **Состояние фильтров и сортировки – в адресе страницы.** Ссылку можно отправить коллеге, «назад» возвращает к тому же виду.
- **Сохранённые представления** («Мои на согласовании», «Просроченные по моему подразделению»): системные + свои; одно можно сделать представлением по умолчанию; изменения в открытом представлении помечены «не сохранено» с выбором «Сохранить / Сохранить как новое / Сбросить». Параметры в адресе важнее представления по умолчанию.
- Пустой результат фильтра – отличай от пустого списка: «По этим фильтрам ничего не найдено» + «Сбросить фильтры».

### 3. Массовые действия

- Чекбокс на каждой строке, «Выбрать все» в заголовке. После выбора всех на странице – предложение «Выбрать все 1 248».
- При выборе появляется **контекстная панель действий** (над таблицей или прилипшая снизу) со счётчиком «Выбрано: 15» и действиями только для пачки.
- Перед необратимым массовым действием – предпросмотр: сколько записей изменится, сколько пропущено и почему («3 заявки уже согласованы – их пропустим»).
- После – итог с результатом по каждой группе и возможностью отменить или скачать список ошибок. Частичный успех – нормальный исход, его надо показать честно.
- Действие недоступно части выбранных из-за прав – не блокируй всю пачку, выполни для доступных и объясни про остальные.

### 4. Карточка записи (CRM-карточка)

```
┌─────────────────────────────────────────────────────────────┐
│ Мария Соколова · Ведущий аналитик   [В штате]  [Действие ▾]│
│ Отдел аналитики · Руководитель: И. Петров · Стаж 3 г. 2 мес │
├───────────────────────────────────────┬─────────────────────┤
│ Следующий шаг: согласовать отпуск     │ Ключевые поля       │
│ 12–25 авг. Срок – завтра  [Согласовать]│ Табельный  004812   │
├───────────────────────────────────────┤ Грейд      12       │
│ [Обзор] [Документы 4] [Отпуска] [⋯]   │ Остаток отп. 14 дн. │
│                                       ├─────────────────────┤
│ История                               │ Связанное           │
│ • Сегодня 10:12 – Петров запросил … │ Заявки (3)  ›       │
│ • 3 авг – Изменён грейд 11 → 12     │ Документы (4) ›     │
└───────────────────────────────────────┴─────────────────────┘
```

- **Шапка**: кто/что это, статус, 3–5 ключевых атрибутов, главное действие. Шапка прилипает при прокрутке в компактном виде.
- **Следующий шаг** – самое ценное на карточке: что от пользователя ждут и к какому сроку. Если ничего не ждут – блок не показывается.
- **История (таймлайн активности)** на каждой записи: кто, что, когда изменил, комментарии, письма, события систем. Это и аудит, и способ вспомнить контекст после перерыва. Изменения полей – в виде «было → стало».
- **Связанные объекты** – превью по 3–5 штук со ссылкой «Все (N)», и действия прямо в превью (паттерн «хаб»).
- **Вкладки** – для групп информации, которые нужны разным ролям или в разные моменты. Не прячь во вкладку то, что нужно каждый раз.
- **Заметки и комментарии с упоминаниями** – люди возвращаются к записи через дни и должны понять, на чём остановились.

### 5. Редактирование

| Способ | Когда |
|---|---|
| Inline (по клику на значение) | Одно поле, частое изменение, легко откатить: статус, ответственный, дата |
| Боковая панель | Несколько связанных полей, нужен контекст списка |
| Страница или режим редактирования | Много полей, проверки между полями, высокая цена ошибки (оклад, реквизиты) |
| Мастер | Редкий длинный процесс |

- Редактируемость видна по наведению (иконка карандаша или курсор). Сохранение – `Enter` или галочка, отмена – `Esc`. После сохранения – короткий знак успеха у поля.
- Если отредактированная строка перестаёт подходить под фильтр или сортировку – не убирай её сразу, держи на месте до обновления списка: иначе человек теряет то, что только что сделал.
- Для критичных данных добавляй трение осознанно: отдельный режим, подтверждение с «было → стало», при необходимости – согласование второго лица.
- Длинные формы – автосохранение черновика и признак «Сохранено в 14:02».
- **Конфликты**: если запись изменил кто-то другой – не затирай молча. Покажи, кто и что изменил, и дай выбрать.

### 6. Очереди и согласования

- Вход – список «Ждут вас» с количеством, сроком и признаком просрочки. Сортировка по сроку.
- Карточка элемента очереди содержит **всё для решения** без перехода в другие разделы: что просят, контекст (остаток отпуска, пересечения в команде, лимит бюджета), история.
- После решения – сразу следующий элемент, а не возврат к списку («Согласовано. Следующая: 2 из 12»).
- Отклонение требует причины; причина видна заявителю.
- Массовое согласование однотипного – с предпросмотром (см. массовые действия).
- Делегирование на время отсутствия – явно и с датами.

### 7. Скорость и клавиатура

- **Бюджет отклика**: реакция на действие до 100 мс ощущается мгновенной, до ~0,4 с – без потери ритма; дольше – прогресс. Для длинных операций (выгрузка, массовое изменение) – фоновая задача с уведомлением о готовности, человек продолжает работать.
- **Оптимистичный интерфейс**: безопасные обратимые действия (сменить статус, назначить ответственного) применяются сразу, синхронизация – в фоне; при ошибке – откат с понятным сообщением. Для денег, кадровых приказов и необратимого – только после ответа сервера.
- **Отмена вместо «Вы уверены?»** для обратимых действий: «Заявка архивирована · Отменить» на 5–10 секунд.
- **Скелетоны** в форме контента, а не крутилка на весь экран. Загружай первым то, что видно сверху.
- **Горячие клавиши**: навигация по списку (`J/K` или стрелки), открыть (`Enter`), назад (`Esc`), частые действия по одной клавише, `?` – список сочетаний. Сочетания видны в подсказках к кнопкам и в палитре: так новичок их выучит.
- Порядок фокуса логичный, фокус всегда виден – клавиатурный эксперт и пользователь скринридера выигрывают одинаково.

### 8. Плотность

- Плотность – настройка пользователя, а не решение дизайнера за всех. По умолчанию – **обычная**: компактная хуже читается людям со слабым зрением и труднее для попадания курсором. Компактная – по выбору, сохраняется для всего сервиса.
- Ориентиры высоты строки таблицы: компактная ~40 px, обычная ~48 px, свободная ~56 px. Основной текст в компактном режиме – не меньше 13 px.
- Плотность – это меньше пустоты, а не меньше иерархии: заголовки, группы и выравнивание остаются.
- Реализация – токенами (`--space-*`, `--row-height`) с переключением атрибутом на корневом элементе, а не отдельными стилями.

### 9. Статусы и сигналы

- Статус – первоклассный элемент: виден в строке списка, в шапке карточки, в навигации (счётчики), а не только внутри записи.
- Набор статусов маленький и описан в глоссарии: у каждого – цвет, текст, иконка и значение «что дальше». Цвет никогда не единственный носитель смысла.
- Сроки: «через 2 дня», «просрочено на 1 день» рядом с датой. Просрочка – единственное, что заслуживает яркого цвета в списке.
- Если данные пришли из другой системы – время актуальности («Данные 1С на 09:40») и признак, что синхронизация не прошла.

### 10. Роли и права

- Недоступное **лучше скрыть**, если человек и не должен знать о функции. Если должен знать (видит запись, но не может изменить) – покажи неактивным с объяснением и путём: «Изменить может HR-партнёр подразделения · Запросить изменение».
- Ошибка прав – никогда «Обратитесь к администратору» без имени и способа: скажи, у кого есть права или как их запросить.
- В прототипе – переключатель роли, чтобы показать разницу экранов.

### 11. Дашборды

- Каждый виджет отвечает на вопрос и ведёт к действию: «Сколько согласований просрочено → открыть список». Метрика без перехода – украшение.
- 5–7 виджетов на экран; сверху – то, что требует внимания сейчас, ниже – тренды.
- Число без сравнения бессмысленно: рядом – норма, прошлый период или цель.
- Клик по любому числу – переход в отфильтрованный список (drill-down) с тем же фильтром в адресе.
- Для графиков – скилл `dataviz`, если он доступен.

### 12. ИИ-помощник в рабочем интерфейсе

Исследование SAP 2026 года о доверии к ИИ-агентам в бизнесе: важнее всего пользователям **контроль человека**, затем надёжность, затем приватность данных и учёт контекста. Сильнее всего на выбор влияет прозрачность (что сделано, что дальше, на каких данных, почему), затем предупреждение о низкой уверенности.

- **Боковой помощник, а не главный путь.** ИИ вызывается там, где идёт работа (на записи, на выборке), и всегда отменяем. Основной сценарий работает без ИИ.
- **Черновик, а не действие.** ИИ готовит: письмо, ответ на обращение, заполнение полей, сводку по карточке. Человек видит, правит и сам применяет. Поля, заполненные ИИ, помечены до подтверждения.
- **Источники и основания**: на каких записях, документах и датах построен ответ, ссылки на них. Предупреждение, если уверенность низкая или данных мало.
- **Подтверждение человеком для действий с последствиями** – изменение данных о людях, деньги, отправка от имени пользователя. Перед применением – список изменений «было → стало».
- **Права ИИ = права пользователя.** Ответ не показывает того, что человек сам не может видеть.
- **Видимость работы агента**: шаги – выполнено / идёт / дальше, возможность остановить; если агентов несколько – видно, какие активны.
- **Быстрое исправление**: перегенерировать, уточнить запрос, отредактировать вручную – без начала заново.
- **Язык**: не очеловечивать («думаю», «понимаю»); действия называть по задаче: «Сделать сводку», а не «Спросить ИИ».

## Применение в прототипе

Сложный интерфейс нельзя проверить на трёх строках «Иванов Иван». В HTML-прототипе (см. `prototyping`):

- **Объём данных реальный**: 150–300 записей в списке, длинные ФИО и названия подразделений, пустые поля, просрочки, записи в разных статусах, конфликтные случаи.
- **Работают**: сортировка, фильтры с отражением в адресе, выбор и массовое действие с предпросмотром, открытие записи в панели и на странице, `Ctrl/⌘+K`, 3–5 горячих клавиш, отмена.
- **Переключатели для ведущего**: роль, плотность, состояние (пусто / загрузка / ошибка интеграции / нет прав).
- **Токены в `:root`**: цвета по смыслу (акцент, успех, предупреждение, ошибка, нейтральные), шкала отступов, высоты строк для двух плотностей. Если у компании есть дизайн-система – её токены и компоненты, а не свои.
- **Визуально спокойно**: системный или нейтральный шрифт, один акцентный цвет, иерархия через вес и размер, а не через рамки, тени и плашки. Красивое и уникальное в рабочем интерфейсе – вторично (в отличие от лендинга).
- Заготовки экранов по архетипам – в `references/screen-templates.md`.

## Самопроверка

- [ ] Есть модель работы: роли, объёмы, топ-5 действий по частоте и топ-3 по цене ошибки.
- [ ] Для каждого экрана выбран архетип, и он соответствует задаче.
- [ ] Самые частые действия – в один клик или одну клавишу; есть `Ctrl/⌘+K`.
- [ ] Фильтры и сортировка в адресе; есть сохранённые представления, если списком пользуются ежедневно.
- [ ] Массовые действия с предпросмотром и честным итогом при частичном успехе.
- [ ] У записи есть своя страница, шапка со статусом и следующим шагом, история изменений.
- [ ] Обратимое – с отменой, необратимое и дорогое – с подтверждением «было → стало».
- [ ] Плотность переключается, по умолчанию обычная.
- [ ] Статусы: цвет + текст, сроки и просрочки видны в списке.
- [ ] Права: скрыто или объяснено, есть путь запросить.
- [ ] ИИ: черновик на проверку, источники, подтверждение действий, видимые шаги.
- [ ] Прототип проверен на 200+ записях и в узком окне ноутбука (1280–1366 px).
- [ ] Прошёл `ux-review` (эвристики и WCAG 2.2 AA).

## Анти-паттерны

- **Витрина вместо рабочего места**: крупные карточки, градиенты и иллюстрации там, где человек обрабатывает 150 записей в день.
- **Всё в модалках**: открыть запись, отредактировать, посмотреть историю – и каждый раз потерять список.
- **Таблица со всеми 40 полями** по умолчанию, без настройки колонок.
- **Фильтры, которые сбрасываются** при возврате из карточки.
- **«Вы уверены?» на каждое действие** – люди перестают читать и подтверждают и опасное.
- **Тихий частичный успех**: «Готово» после массового действия, где 7 из 50 не прошли.
- **Цвет как единственный сигнал** и десять оттенков статусов.
- **Disabled-кнопка без объяснения**, «Нет доступа» без пути.
- **ИИ, который сам меняет данные** или выдаёт ответ без источников.
- **Компактный режим по умолчанию** «потому что эксперты» – решает пользователь.
- **Дашборд из чисел без сравнения и без перехода в список.**
